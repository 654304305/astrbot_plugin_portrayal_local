# astrbot_plugin_portrayal_local

_✨ 人物画像插件 ✨_

根据群友的聊天记录，调用 LLM 分析群友的性格画像——支持综合画像、正/负画像、红娘匹配、克隆人格，本地缓存聊天记录，无需反复爬取协议端。

## 💡 介绍

插件会持续把群聊消息存入本地 SQLite 缓存（跨重启持久化），在收到画像指令时，从缓存中提取目标群友的最近聊天记录交给 LLM 分析，生成该群友的性格画像报告。

相比每次都向协议端重新爬取历史消息的方案，本地缓存：

- 速度快、Token 消耗可控，不受不同 OneBot 协议端「获取历史消息」接口差异的影响；
- 支持按群 / 按人两级容量上限裁剪，长期运行也不会无限膨胀；
- 可选记录机器人自身的发言，把 bot 也纳入画像分析。

> 输出直接以长文本形式发送。如需转图片，推荐配合 [输出增强插件](https://github.com/Zhalslar/astrbot_plugin_outputpro) 使用。

## 📦 安装

  克隆源码到插件目录后重启 AstrBot：

```bash
cd /AstrBot/data/plugins
git clone https://github.com/654304305/astrbot_plugin_portrayal_local
```

## ⚙️ 配置

在 AstrBot 面板 → 插件管理 → astrbot_plugin_portrayal → 操作 → 插件配置 中调整。

### LLM 配置

| 配置项 | 默认值 | 说明 |
|:---|:---:|:---|
| `provider_id` | 空 | 用于画像分析的 LLM 提供商。留空或填写的提供商不存在时，使用当前会话正在使用的提供商 |
| `retry_times` | 2 | LLM 调用失败时的重试次数（1~5） |

### 消息查询配置

| 配置项 | 默认值 | 说明 |
|:---|:---:|:---|
| `record_bot_reply` | false | 是否记录机器人自己的消息 |
| `record_bot_all` | false | 记录 bot 的全部发言（含其他插件发出的消息）；关闭则仅记录 LLM 生成的回复 |
| `max_msg_count` | 100 | 单次画像分析默认提取的最大消息条数（实际受单人缓存上限约束，取两者较小值） |
| `max_group_cache_size` | 4000 | 每个群本地缓存的最大消息条数 |
| `max_user_cache_size` | 100 | 单群内每个用户（含 bot）保留的最新消息条数，**优先于群上限执行**：先按人裁、再按群裁 |
| `group_trim_ratio` | 10 | 群裁剪触发缓冲比例（%）。消息数达到上限 × (1 + 比例) 时才触发裁剪，0 表示无缓冲 |
| `user_trim_ratio` | 20 | 单人裁剪触发缓冲比例（%），逻辑同上 |

### 其他

| 配置项 | 默认值 | 说明 |
|:---|:---:|:---|
| `inject_prompt` | false | 是否把已生成的画像注入到后续提示词中 |
| `entry_storage` | — | 提示词命令配置，可在 WebUI 中自定义增删 |

## ⌨️ 使用说明

### 🛠️ LLM 工具（自然语言调用）

除了下文的指令触发外，插件还会通过 `add_llm_tools` 注册一个名为 `generate_portrait` 的函数调用工具。注册后，Bot 的人格模型可以在**自然语言对话中自主识别画像意图**并调用该工具——用户无需记住任何指令格式，直接说「评价一下我」「@某人 是个什么样的人」「找对象」等日常表达即可触发画像生成，由 LLM 自动判定风格（画像/正画像/负画像/找对象）与目标用户。这是本插件区别于纯指令插件的核心特性。

插件的命令分两类：

- **内置命令**：通过 `@filter.command` 注册，固定不可改，会自动出现在 WebUI 的插件指令列表中；
- **提示词命令**：在 `builtin_prompts.yaml` / 插件配置「提示词配置」里定义，可自行增删；它们由通用监听器响应，WebUI 不会单独列出。

### 触发规则与写法

```
画像 @群友 [条数]
```

- 末尾的 `[条数]` 可省略，省略时使用 `max_msg_count`；填写则指定本次提取最近多少条记录，例如 `画像 @群友 10`；
- **At 段必须紧邻命令词**：命令词与 @ 之间不允许夹带其他内容。指令开头可以 @ 机器人（如 `@bot 画像 @群友`），但「前面多一个字都算闲聊」，以此避免长句中混杂 @ 导致的误触发；
- 无法确定 QQ 号时可使用语义化目标 `previous_speaker`（刚刚说话的人）。

### 指令表

#### 提示词命令（可在插件配置中自定义增删）

| 指令 | 说明 |
|:---:|:---:|
| `画像 @群友 [条数]` | 综合性格画像（含优点/缺点/相处建议） |
| `正画像 @群友 [条数]` | 偏优点向的画像 |
| `负画像 @群友 [条数]` | 偏缺点向的画像（理性审判风格） |
| `找对象 @群友 [条数]` | 根据聊天记录推荐适合的对象类型（红娘匹配分析） |
| `克隆人格 @群友 [条数]` | 生成可用于「切换人格」的 system prompt，保存为该群友的克隆模板 |

> 部分提示词条目可在配置中设为「仅管理员可用」。

#### 内置命令

| 指令 | 权限 | 说明 |
|:---:|:---:|:---:|
| `查看画像 @群友` | 所有人 | 查看本地已生成的画像 |
| `切换人格 @群友` | Admin | 把当前会话切到该群友的克隆人格，并同步 bot 的 QQ 昵称/头像。**前置：需先执行「克隆人格 @群友」生成模板** |
| `恢复人格` | Admin | 一键还原：恢复默认人格、清空当前对话历史、还原 bot 昵称/头像 |

## 🗃️ 缓存与数据

- 消息缓存与已生成的画像持久化存储在插件的 `data/cache` 目录下，重启不丢失；
- 画像结果会做本地缓存，`查看画像` 直接读取，不会重复消耗 Token；
- 即使本次缓存的消息数少于配置上限，也会直接返回已缓存的文本，避免不必要的重新扫描。

## 📌 注意事项

- 画像质量取决于缓存的聊天记录数量，刚装好的插件需要跑一段时间积累消息；
- 条数越多，画像越准确，但消耗的时间和 Token 也越多，请按需调整；
- `record_bot_all` 开启后会记录其他插件发送的消息，若群内插件发言频繁，注意控制缓存上限。
